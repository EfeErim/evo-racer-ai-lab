# EvoRacer AI Lab v1.1.1

Status: locally verified executable, recoverable Track and Saved-runs startup
reads, resilient shutdown lifecycle, route-owned Track commands, unconfirmed-Start Saved-run
recovery, accessible setup semantics, route-owned Review validation, Track
Builder, owned Track imports, route-owned Saved actions, replay integrity,
responsive UI,
Start/run recovery, keyboard-state, and local-library error correction; not yet
published.

For a local source build, open `release\EvoRacer\EvoRacer.exe` directly. The
ZIP is only a parallel distribution artifact.

## Fixed

- Restored `EvoRacer.exe` as the root-level Windows entry point.
- Removed the requirement to open `EvoRacer.cmd`.
- Restored the exact PyInstaller `onedir` build and license boundary.
- Added release acceptance that fails unless the EXE directly owns the
  loopback service and runs without installed Node.js or Python.
- Exit now enters a focused `Shutting down EvoRacer…` state immediately and
  permits only one shutdown request. A successful shutdown permanently owns the
  page so delayed IPC responses cannot rebuild the application shell; a rejected
  shutdown restores the interface and exposes the exact local failure.
- Kept Python-derived preview geometry visible while an editor loop is invalid,
  without allowing that draft to be selected, saved, or exported.
- Expanded assisted closure with a bounded rollback of up to six invalid
  trailing pieces while retaining the 200-candidate limit.
- Added deterministic generator version 2 layouts with varied straights,
  45-degree corners, chicanes, and hairpins for the existing difficulty modes.
- Hardened corrupt-run isolation, NEAT network-key validation, track
  self-contact detection, controller output validation, and asynchronous UI
  state ownership after a second repository-wide audit.
- Generator form edits now mark the previous Python-verified preview as stale
  immediately while retaining the seed that produced it.
- Saved-run and result-comparison tables now keep wide content inside their own
  scroll container instead of creating page-level horizontal overflow.
- Transient run observation and command failures now preserve the last verified
  snapshot, show the exact operation failure, and recover through automatic
  polling.
- Pause, resume, and stop controls lock while their command is pending, and
  stale observation responses cannot overwrite a newer run-command result.
- Training polling and asynchronous form validation now preserve keyboard
  focus; temporary command failures restore focus to the re-enabled control.
- Settings disclosures retain their open state across edits, and Track Builder
  tabs now provide roving focus, linked panels, arrow/Home/End navigation, and
  predictable open/close focus handoff.
- Track and run commands now identify the failing operation, validate versioned
  responses before rendering, and reject a `deleted: false` response instead of
  presenting a false success.
- Saved-run actions lock while pending and preserve the valid library after a
  resume, export, or delete failure while exposing the exact Python error.
- A rejected or interrupted Start no longer strands the user on a locked
  Training error screen. Rejected settings return to Review for validation;
  an interrupted response keeps the valid setup, identifies the result as
  unknown, and links to Saved runs before an explicit retry.
- Welcome now refreshes the Python-owned run library on every entry, so the
  interrupted-Start recovery link can reveal a run created after the prior list
  snapshot. Refresh failures expose their exact local HTTP/connection cause and
  do not erase a still-relevant dismissed-action notice.
- Completed and stopped Saved runs now provide **Open results** instead of a
  permanently disabled Resume control. Opening revalidates the RunV1, compiles
  its stored track, and restores Results and champion replay without advancing
  training.
- Observation parsing now rejects terminal result metadata whose run identity,
  status, or generation counts disagree with its snapshot, and rejects results
  attached to non-terminal snapshots.
- Track and Saved runs refreshes now use monotonic request ownership. A delayed
  startup response can no longer overwrite a newer save/delete/terminal list;
  Track refreshes also merge into the current workspace after the response so
  stale state cannot close the builder or discard current editor/generator work.
- Initial preset-preview and Track Library failures no longer remain as generic
  previews or an endless loading spinner. Entering Track retries unavailable
  sources automatically; repeated exact local errors provide independent Retry
  actions, and successful responses restore all three Python geometries and the
  versioned local library without reloading the application.
- Initial Saved runs failures now open the recovery panel automatically, expose
  the exact local error as an alert, and provide **Retry saved runs**. Welcome
  entry and manual retry use an explicit loading state, prevent duplicate
  requests, and restore the versioned run list without a page reload. A failed
  later refresh preserves the last valid rows and their actions beside the
  recoverable error instead of replacing the complete library.
- Successful automatic Saved runs recovery now clears the prior error instead
  of restoring it as the new status. Track Library retry reports completion,
  generator inputs lock during Python generation, and Track Builder command
  errors are announced as alerts.
- Results replay controls now clamp every action to the available Python frame
  range. Empty replay payloads, invalid sampling intervals, negative times, and
  non-increasing frame times are rejected before rendering; a corrupt Saved
  replay keeps the valid run library visible and retryable with its exact error.
- Saved-run Open, Resume, Export, and Delete responses now belong to the Welcome
  route where the action started. Leaving and returning cannot let an old
  response unexpectedly open Results/Training or start a download; completed
  background Resume/Delete operations refresh the Python-owned library.
- TrackV1 import now shows `Importing…`, locks the file picker, and owns a
  monotonic request version. Closing Track Builder or leaving Track prevents a
  late Python compile from reopening the workspace or replacing newer editor
  state.
- Track Builder Assist, Generate, Save, and Delete responses now belong to the
  route, open Builder, and tool where they started. Late generated/repaired
  presentation state is ignored after navigation, while a dismissed Save/Delete
  refreshes the Python-owned library because the local mutation may already have
  completed. Save exposes `Saving…` and a live status while pending.
- Review validation now belongs to the Review visit and a monotonic request
  version. Leaving Review cancels its pending presentation; a late response
  cannot reopen Review, unlock Start, or complete a newer check of the same
  draft.
- Preset radios now have concise explicit accessible names and ignore their
  decorative track SVGs. Algorithm is linked to its help text, and inactive
  Track Builder tabs retain hidden panel targets for complete ARIA relationships.

## Run

1. Extract `EvoRacer-Windows-x64.zip` completely.
2. Open `EvoRacer\EvoRacer.exe`.

Do not run the application from inside the ZIP. Keep the complete extracted
folder together.
